# Finite conformance evidence

A conformance result identifies a comparison, input population and artifact revision. It is useful precisely when those limits remain visible.

The kit's [L0 command](../assure/conformance.md) exercises the shipped boundary corpus. Receipt-profile tests distinguish expected agreement from intentional authority-policy differences. Browser and CLI compatibility examples can expose concrete mismatches such as decimal canonicalization, but a passing string-only receipt cannot establish the full numeric contract.

For these guides, a fresh Seal demo BLOCK receipt was checked in the product, browser and kit using the matching demo key. The browser also refused changed arguments. That is a specific cross-tool example, not a new universal conformance claim.

Keep the exact inputs, source revisions, stdout/stderr, exit status and expected negative-control diagnostic with an evidence report. A nonzero exit caused by a missing file is not a successful tamper test.

[Source versions](sources.md) identify this pass. [Correspondence](correspondence.md) and [current guarantees](../assurance/current-scope.md) name what remains outside its evidence.
